What .cesvu Deliberately Does Not Do
No public-key encryption. .cesvu is passphrase-only. There is no key exchange protocol, no recipient stanzas, no KEM. The passphrase is the shared secret, distributed out-of-band by the user. A KEM solves a problem .cesvu doesn't have.

No compression. Compression causes unbounded memory usage (7z's LZMA dictionary), enables CRIME/BREACH-style oracle attacks, and is a separate concern. Use zstd externally if needed.

No signing. Encrypt and sign are separate operations with different threat models. Use a dedicated signing tool (like minisign) alongside .cesvu.

No archive/multi-file. .cesvu encrypts one file at a time. For multi-file archives, use tar (uncompressed) and encrypt the tarball or zip.

No algorithm negotiation. One cipher mode (secretstream_xchacha20poly1305), one KDF (Argon2id), one format version. No --cipher flag, no downgrade risk.

The Bottom Line
.cesvu is a thoroughly specified passphrase-only encrypted file format. It combines:

Argon2id with domain separation, per-file parameters, and a scheduled ratcheting cadence — the most thoroughly specified KDF deployment of any passphrase-based file format
XChaCha20-Poly1305 secretstream with the full header bound as associated data — streaming AEAD with header integrity transitively guaranteed
Encrypted metadata preservation including filename, MIME type, and timestamp — more metadata fields than any comparable format, all encrypted, all auto-restored
Fast wrong-passphrase rejection via keyCheck with an explicit security boundary — a named, enforced separation between unauthenticated fast-reject and authenticated verification
The only enforced passphrase quality system (2/3 profiles with documented entropy)
The only plaintext preamble (self-documenting encrypted files)
The only auth-state-classified error code taxonomy (deliberately ambiguous pre-auth)
The only encrypted file format with a normative cross-language Unicode normalization specification for passphrase interop
The only filename safety specification (5 normative rules including Windows device stems and RTL override attacks)
The only encryption format that natively supports emoji passwords with enforced entropy requirements
An encryption format that grants greater privileges (non-entropy-checked passphrase, and preamble modification) to CLI and headless users (Python, NPM package) — with greater technical abilities comes greater responsibility.
For passphrase-based, single-file encryption with metadata preservation and cross-platform consistency, there is nothing else like it.
